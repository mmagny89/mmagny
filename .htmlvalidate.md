# Règles html-validate désactivées — justifications

La porte `balisage` du workflow `.github/workflows/qualite.yml` exécute
`html-validate` sur `site/**/*.html`. Une porte rouge en permanence ne protège
de rien : chaque règle désactivée ci-dessous l'est pour une raison précise,
et le tableau doit être relu si le site change de nature.

| Règle | Pourquoi elle est désactivée |
|---|---|
| `doctype-style` | La règle veut `<!DOCTYPE html>` en majuscules. `<!doctype html>` est strictement équivalent en HTML5 et c'est la forme employée par le site. Préférence typographique, pas un défaut. |
| `empty-heading` | Les deux `<h2>` vides (`#homeModalTitle`, `#modalTitle`) sont les titres des modales, remplis à l'ouverture par `assets/js/`. Le balisage est correct ; c'est l'analyse statique qui ne voit pas le contenu. |
| `void-style` | Le site mélange `<br>` et `<br/>`. Sans effet sur le rendu. |
| `no-inline-style` | Quelques styles inline ponctuels, assumés à côté de Tailwind. |
| `require-sri` | Les CDN tiers (polices, Font Awesome) ne sont pas épinglés par SRI. À reconsidérer — voir README.docker.md, section « Reste à faire ». |
| `script-type` | `<script>` sans `type` vaut JavaScript en HTML5. |

Toute autre règle reste **bloquante** : les corriger, jamais les ajouter ici
sans une ligne de justification.
